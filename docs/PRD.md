# PRD: 병동 EMR 스트림의 보정, 알람, 서빙

이 문서는 합성 벤치 `vital-stream-triage`가 제품으로 커질 때의 요구사항이다. 지금 저장소는 그 제품이 아니다. 임상 장치도 아니고, 에이아이트릭스 바이탈케어나 뷰노의 모델을 재현하지 않는다. 측정값은 [BENCHMARK_RESULTS.md](../BENCHMARK_RESULTS.md)의 시드 0 실행이다.

## 1. 문제

일반병동 EMR에서 악화 점수를 켜면 두 가지가 동시에 문제다. 혈액검사는 하루 한두 번이라 시간축의 대부분이 비어 있고, 점수를 그대로 호출하면 위양성이 호출을 메운다. 1,000병상 창이 같은 시각에 들어오면 요청을 한 건씩 처리하는 큐는 꼬리 지연이 길어진다.

현장 문헌은 모니터 알람의 위양성이 이미 크다고 적는다. Sendelbach와 Funk는 임상 알람의 72–99%가 거짓 알람이라고 정리했다. Paine 등의 체계적 고찰은 생리 모니터 알람의 74–99%가 조치로 이어지지 않았다고 적었다. 이 비율은 그 논문들의 모니터 알람이지, 이 벤치의 92건이 아니다.

## 2. 사용자와 범위

사용자는 병동 신속대응 흐름을 설계하는 PM과, 그 흐름의 점수·큐를 구현하는 엔지니어다. 이 버전이 제공하는 것은 세 가지 실험과 로컬 대시보드다.

| 포함 | 제외 |
| --- | --- |
| 1시간 격자, 합성 19채널, 인구 평균으로의 고정 τ 감쇄 | 학습되는 GRU-D 감쇄, 은닉 상태 감쇄 |
| 악화 소프트맥스 > 0.7 과 엔트로피 < 0.3 nat의 단일 게이트 | 호출 / 관찰 큐의 두 경로. 아래 4절은 요구사항이지 구현이 아니다 |
| 한 CPU 스레드, 동시 유입 1,000창, max batch 128 | NVIDIA Triton, TensorRT, Kafka, 병원 EMR 접속 |
| 검사 11종의 마지막 채혈 이후 경과 시간 | 바이탈 결측 마스크 전체, 처방 의도 모델 |

19채널은 바이탈 6, 검사 11, 나이, GCS다. 검사 쪽의 헤모글로빈과 BUN은 이 벤치가 11종을 채우려고 넣은 통상 항목이다. VC-MAES/VC-SEPS 프리프린트는 핵심 바이탈 5종과 나이에 더해, 있을 때 SpO2, GCS, 빌리루빈, 젖산, 크레아티닌, 혈소판, 동맥혈 pH, 나트륨, 칼륨, 헤마토크릿, 백혈구, 중탄산염, CRP를 쓴다고 적는다. 개수는 같아도 목록은 같지 않다. pH와 중탄산염이 있고, 헤모글로빈과 BUN은 그 문장에 없다.

## 3. 성공 기준

시드 0, 환자 400, 48시간, 검증 환자 120, 병상 1,000, 한 CPU 스레드.

| ID | 기준 | 이번 실행 |
| --- | --- | --- |
| I-1 | 11종 표준화 MSE가 time-decay < forward-fill < zero-fill | 0.723 < 0.870 < 412.978 |
| I-2 | time-decay의 감쇄 상관이 forward-fill보다 큼 | 0.485 > 0 |
| A-1 | 위양성 건수가 35% 이상 감소 | 92 → 39, 57.6% |
| A-2 | 융합 정밀도 ≥ 기준 정밀도, 재현율 > 0 | 0.480 ≥ 0.352, 재현율 0.200 |
| S-1 | micro-batch P99 < 50 ms | 6.10 ms |
| S-2 | micro-batch 처리량 > 순차 처리량 | 163,580 / 5,254 병상/초, 31.1배 |

지연은 다시 재면 움직인다. I와 A는 시드가 같으면 같다. 젖산 표준화 MSE는 19.858, 2.807, 2.486이다. 방향은 I-1과 같지만 11종 가운데 잔차가 가장 크다.

## 4. 다음 제품 요구: 호출과 관찰을 나눈다

단일 게이트를 유일한 호출로 쓰면 재현율이 0.278에서 0.200으로 떨어진다. 기준 알람 142건 중 융합이 버린 67건은 참 14건, 거짓 53건이다. 버린 집합의 정밀도는 14/67 = 0.209다. 거짓이 많지만 참 14건이 들어 있다.

그래서 다음 버전은 한 점수를 두 경로로 나눈다.

| 경로 | 조건 | 이번 실행에서 해당 건수 | 하는 일 |
| --- | --- | --- | --- |
| 즉시 호출 | 악화 확률 > 0.7 그리고 H < 0.3 nat | 75건, 정밀도 0.480 | 신속대응이 바로 본다 |
| 관찰 큐 | 악화 확률 > 0.7 그리고 H ≥ 0.3 nat | 67건, 정밀도 0.209 | 같은 근무 안에 다시 본다. 버리지 않는다 |
| 침묵 | 악화 확률 ≤ 0.7 | 나머지 평가 시간 | 호출하지 않는다 |

코드 블루는 병원 비상호출 규약이다. 이 벤치의 라벨은 합성 악화 구간이지 심정지가 아니다. 면접에서 즉시 호출을 코드 블루라고 말하지 않는다.

이 분기는 `triage_engine.py`에 아직 없다. 대시보드 슬라이더는 컷을 바꿔 건수가 어떻게 달라지는지만 보여 준다.

## 5. 연동 요구

원내 연동의 데이터 계약은 HL7 FHIR다. 구현하지 않았다.

| 리소스 | 이 벤치의 대응 |
| --- | --- |
| `Patient` | 나이. 식별자는 만들지 않는다 |
| `Encounter` | 48시간 추적 한 건 |
| `Observation` | 바이탈과 검사. `valueQuantity`, `effectiveDateTime`, 결측이면 값 없이 상태만 |

스트림은 FHIR REST가 한 경로이고, 같은 `Observation` JSON을 이벤트 버스로 미는 것이 다른 경로다. Kafka 토픽과 Triton은 이 저장소에서 실행하지 않았다. Triton dynamic batching은 상태가 없는 모델에서 요청을 모아 `max_queue_delay` 안에 배치를 만드는 서버 기능이다. 여기의 큐는 그 구조의 단일 프로세스 축소판이다. 1,000개 창이 이미 도착해 있는 버스트이고, 지연 상한으로 배치를 닫는 실험은 아니다.

## 6. 면접에서 말할 수 있는 문장

아래 세 문장은 이번 실행과 코드 범위 안에서만 말한다.

**정보성 결측.** 결측은 빈 칸만이 아니라 측정이 없었다는 정보다. GRU-D는 마지막 값을 인구 평균 쪽으로 감쇄하고, 마스크와 경과 시간을 함께 넣는다. 이 버퍼는 그 입력 감쇄의 고정 τ 경우다. 가중치는 학습하지 않는다. 젖산은 감쇄 뒤에도 표준화 MSE 2.49가 남는다. 관측되지 않은 상승은 마지막 값에 없기 때문이다. 헤드는 검사 11종의 경과 시간을 채널로 받는다. 생성기의 결측은 48시간에 패널 두 번이고, 악화 환자의 절반만 경보 구간에 채혈이 들어간다. 의사의 처방 의도를 학습한 모델은 아니다.

**두 단계 알람.** 엔트로피 0.3 nat는 위양성을 92건에서 39건으로 줄이고 정밀도를 0.352에서 0.480으로 올리며, 재현율을 0.278에서 0.200으로 내린다. 버린 67건에 참 14건이 있으므로, 제품은 그 67건을 삭제하지 않고 관찰 큐에 둔다. 이 분기는 요구사항이다. Ovadia 등은 분포가 이동하면 소프트맥스 신뢰도가 과신하기 쉽다고 보였다. 이 게이트는 합성 분포 안에서의 소프트맥스 엔트로피이고, 앙상블도 분포 이동 실험도 아니다.

**원내 스케일 지연.** 이 CPU의 스레드 하나에서 1,000창이 동시에 오면 순차 P99는 188.7 ms, 128 마이크로배치는 6.1 ms다. 처리량은 초당 5,254병상에서 163,580병상으로, 31.1배다. Triton을 띄운 측정이 아니고, EMR 서버 부하 시험도 아니다.
